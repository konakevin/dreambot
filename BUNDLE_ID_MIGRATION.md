# Bundle ID Migration Playbook (DreamBot)

How to rename the iOS/Android app bundle identifier across the entire system. Written 2026-05-02 when migrating from `com.konakevin.radorbad` (relic) to `com.konakevin.dreambot`.

---

## Critical decision: pre-launch vs post-launch

**Pre-launch** (app NOT yet on App Store): clean rename, ~30 minutes total. Steps 1-3 below.

**Post-launch** (app IS on App Store under the old bundle ID): **bundle IDs are immutable in App Store Connect once an app is published.** You can't rename — you must:
- Create a NEW App in App Store Connect under the new bundle ID
- Existing users on the old app stay on the old app (they don't auto-migrate)
- Lose all reviews, ratings, install base on the new listing
- Either keep the old app for sale alongside the new one, or yank the old app from sale (existing users keep what they have)
- This is a one-way decision with user-impact tradeoffs. Only do it if brand confusion is meaningful, OR before you have meaningful install base.

The rest of this doc assumes pre-launch (or post-launch where you've decided to take the hit).

---

## Phase 1 — In-app code changes (~5 min)

The DreamBot codebase has bundle-ID references in only **3 files** and **8 functional locations**. (Display name, slug, URL scheme, associated domains were already on `dreambot` — only the bundle ID itself was stuck.)

Find all references first:
```bash
grep -rn "com\.konakevin\.OLD_NAME" --include="*.json" --include="*.ts" --include="*.tsx" \
  --include="*.js" --include="*.plist" --include="*.pbxproj" --include="*.entitlements" .
```

Then update:

### 1. `app.config.js`
```js
ios: {
  bundleIdentifier: 'com.konakevin.NEW_NAME', // was: com.konakevin.OLD_NAME
  // ...
},
android: {
  package: 'com.konakevin.NEW_NAME', // was: com.konakevin.OLD_NAME
  // ...
},
```

### 2. `constants/sparklePacks.ts`
Four IAP product IDs:
```ts
{ productId: 'com.konakevin.NEW_NAME.sparkles.25', ... },
{ productId: 'com.konakevin.NEW_NAME.sparkles.50', ... },
{ productId: 'com.konakevin.NEW_NAME.sparkles.100__', ... },
{ productId: 'com.konakevin.NEW_NAME.sparkles.500', ... },
```

### 3. `ios/DreamBot.xcodeproj/project.pbxproj`
Two `PRODUCT_BUNDLE_IDENTIFIER` lines (Debug + Release configs):
```
PRODUCT_BUNDLE_IDENTIFIER = com.konakevin.NEW_NAME;
```
This file is regenerated by `npx expo prebuild --clean`, so editing it manually is OK if you're not doing a clean prebuild. If you ARE running `expo prebuild`, the value will come from `app.config.js` automatically.

### Verify nothing was missed
```bash
grep -rn "OLD_NAME" --include="*.json" --include="*.ts" --include="*.tsx" \
  --include="*.js" --include="*.plist" --include="*.pbxproj" .
```
Should return zero hits in code (docs are fine).

### Documentation cleanup (optional)
README.md, CLAUDE.md, LAUNCH.md, SPARKLE_PAYMENTS_SETUP.md, AUTH_PROVIDERS.md may have stale references. Cosmetic — won't affect runtime.

## Phase 2 — External services (you do these in respective consoles)

**Order matters** — do Apple first since most other services hang off the App ID.

### 2.1 Apple Developer portal (developer.apple.com → Identifiers)
1. Register a new App ID for `com.konakevin.NEW_NAME`. Enable capabilities: **Push Notifications**, **Sign in with Apple**, **Associated Domains** (and any others you use).
2. Optionally disable / mark-as-archived the old `com.konakevin.OLD_NAME` App ID.

### 2.2 App Store Connect (appstoreconnect.apple.com)
1. Create a new app under the new bundle ID.
2. Configure name, primary language, SKU, bundle ID = the one you registered above.
3. Configure App Privacy, App Information, Pricing, etc. (You're starting fresh — none of this carries over from the old app entry, even pre-launch.)
4. If pre-launch: delete the empty `OLD_NAME` app entry to avoid confusion.

### 2.3 App Store Connect → In-App Purchases
1. Under the new app, create the 4 sparkle IAP products with the NEW IDs from `sparklePacks.ts`.
2. Each product needs: reference name, display name, price tier, screenshot, description.
3. Submit each for IAP review (this can be done with the first app submission).

### 2.4 RevenueCat dashboard (app.revenuecat.com)
1. Add a new "App" entry tied to the new App Store Connect app.
2. Upload App Store Connect API key (account-level, can reuse from old setup).
3. Configure the 4 IAP products with the new product IDs in your default offering.
4. **Update RevenueCat API key** in `lib/revenuecat.ts` if it's app-scoped (it is — the iOS key is `appl_xxxx`). Find new key in RevenueCat → Project Settings → API keys.
5. **Update webhook secret** if it changed: Supabase Dashboard → Edge Function Secrets → `REVENUECAT_WEBHOOK_SECRET`.

### 2.5 Supabase Auth providers
1. **Apple Sign In:**
   - Apple Dev → Identifiers → Services ID → either edit existing or create new. Bind to the new App ID. Add Supabase callback URL (`https://<project>.supabase.co/auth/v1/callback`) to "Web Authentication Configuration".
   - Generate (or reuse) a Sign in with Apple Key (`.p8`) — bind to new App ID.
   - Supabase Dashboard → Authentication → Providers → Apple: update Service ID, Key ID, Team ID, paste new private key contents.
2. **Google OAuth:**
   - Google Cloud Console → APIs & Services → Credentials → create new "iOS" OAuth client ID with bundle ID = new bundle ID.
   - Supabase Dashboard → Authentication → Providers → Google: update iOS Client ID. (Web Client ID is unchanged.)
3. **Facebook:**
   - developers.facebook.com → your FB App → Settings → Basic → "iOS" section → update Bundle ID to new bundle ID. App ID itself is unchanged.

### 2.6 APNs (push notifications)
- The APNs auth key (`.p8`) is account-level, not app-level — same key works for both old and new bundle IDs as long as the new App ID has Push Notifications capability enabled (done in 2.1).
- Re-bind via EAS:
  ```bash
  eas credentials --platform ios
  ```
  Choose the new bundle ID, opt to re-upload the APNs key.

### 2.7 Universal Links / Associated Domains
- Site at `dreambotapp.com/.well-known/apple-app-site-association` has the bundle ID embedded:
  ```json
  { "applinks": { "apps": [], "details": [
    { "appID": "TEAMID.com.konakevin.NEW_NAME", "paths": ["*"] }
  ]}}
  ```
- Update this JSON file to point to the NEW bundle ID. Apple caches AASA for ~24h — propagation delay.
- TEAMID is your Apple Developer Team ID (10-char alphanumeric). Find it at developer.apple.com → Membership.

### 2.8 EAS Build / TestFlight
- `eas credentials --platform ios` → provision certificates and provisioning profiles for the new bundle ID.
- `eas build --platform ios --profile preview` (or `production`) → produces a build under the new bundle ID.
- TestFlight tracks builds per-bundle-ID; old TestFlight builds under the old bundle ID stay separate from new builds.

## Phase 3 — Verification

After Phases 1 + 2, verify the system end-to-end:

1. **Local dev build:** `npx expo start` + open in iOS Simulator or device. App should launch as DreamBot under the new bundle ID. Check `Settings → General → iPhone Storage → DreamBot` to confirm the bundle ID.
2. **Auth providers:** test sign-in with Apple, Google, and Facebook. All three should authenticate successfully and create / load a Supabase user.
3. **Push notifications:** trigger a test push (e.g., comment on your own post). Should arrive on the device.
4. **IAP / RevenueCat:** sandbox test purchase of all 4 sparkle packs. Verify webhook fires + sparkles balance updates.
5. **Universal Link:** in Mail or Messages, send yourself a `https://dreambotapp.com/photo/<id>` link. Tapping it should open the app, not Safari.

## Hard rules (no exceptions)

- **Don't use string-find-replace globally without grepping first.** Documentation files (README, etc.) referencing the old bundle ID are FINE to keep — they're just history. Don't bulk-replace and accidentally rewrite git commit messages, comments quoting old issues, etc.
- **Don't manually edit `ios/*.xcodeproj/project.pbxproj` if you're going to run `expo prebuild` afterward.** The prebuild regenerates the file from `app.config.js`. Manual edits get blown away.
- **Don't try to migrate a published App Store listing.** Bundle IDs are permanent in App Store Connect post-publication. New bundle ID = new app = lose history. Decide deliberately.
- **Don't forget the AASA file.** Universal Links silently break if the AASA still references the old bundle ID — taps open Safari instead of the app, with no error message.
- **Don't skip RevenueCat re-config.** IAP products are bundle-ID-scoped. Old product IDs return "Product not found" in the new app.
